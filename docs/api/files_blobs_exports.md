# Files, Blobs, And Exports

Use blobs for large binary content such as photos, PDFs, generated exports, and
attachments. Store the blob hash in a table field and serve the content through
API endpoints.

Blob hash columns can be declared with `table.blobRef("field_name")`. This is a
readability alias for `table.bytes("field_name", 32)`. Existing wider blob hash
columns can preserve their schema with `table.blobRef("field_name", 64)`.

## Upload Bytes

Use `bytesBodyScalar` for uploads. Create the blob outside the table row, then
store the hash and content type in a transaction.

For large authenticated uploads, use `blobBody` instead. The platform stores
the request before the procedure runs, exposes the stored blob hash through
`scalar`, optionally exposes the exact source hash through `sourceHashScalar`
and byte length through `sizeScalar`, and supports its built-in chunked upload
protocol. Set `maxSize` and implement `authorize` when the endpoint needs an
upload-specific limit or authorization check.

```ts
api.post("/photos/{record_id:id}", {
  bytesBodyScalar: "photo_bytes",
  procedure: (s) => {
    s.createBlob(sql`photo_bytes`, { defHashScalar: "photo_blob_hash" });
    s.startTransaction();
    s.modify(sql`
      insert into db.photos (record_id, photo_blob, content_type, captured_at)
      values (record_id, photo_blob_hash, 'image/jpeg', now())
    `);
    s.commitTransaction();
    s.return(sql`json_build_object('ok', true)`);
  },
});
```

Use `s.resizeImage(...)` before `s.createBlob(...)` when the app needs derived
thumbnail or preview blobs.

## Serve Blobs

Fetch the blob hash from the database, set headers, and return the blob.

```ts
api.get("/photos/{photo_id:id}", {
  procedure: (s) => {
    s.defRecord("photo", sql`
      select photo_blob, content_type
      from db.photos
      where id = photo_id
    `);
    s.if(sql`photo.photo_blob is null`, (s) => {
      s.setHttpStatus(404);
      s.return(sql.lit`Not found`);
    });
    s.setHeader(sql.lit`Content-Type`, sql`photo.content_type`);
    s.setHeader(sql.lit`Cache-Control`, sql.lit`max-age=31536000, immutable`);
    s.returnBlob(sql`photo.photo_blob`);
  },
});
```

Use signed or unguessable route identifiers for public links. Use
`Content-Disposition` for PDF/download filenames.

## Typst And PDFs

Put system-owned templates in `templates/*.typ`. Render a template in a
procedure with `s.renderTypst(...)`, then store or return the generated bytes:

```ts
s.renderTypst({
  template: sql.lit`invoice`,
  data: sql`cast(invoice_json as string)`,
  outputFormat: "pdf",
  defPdfOutputScalar: "pdf_bytes",
  assets: [
    { name: "signature.png", data: sql`signature_png_bytes` },
  ],
});
s.createBlob(sql`pdf_bytes`, { defHashScalar: "pdf_blob_hash" });
```

`data` is passed to the Typst template as JSON text. Use `assets` for images or
signatures that the template needs while rendering.

For system-owned static files, put the file under `assets/`. Typst resolves a
relative path from the template's virtual directory: a root template can use
`#image("logo.jpg")` for `assets/logo.jpg`, while
`templates/invoices/report.typ` can use `#image("logo.jpg")` for
`assets/invoices/logo.jpg`. Use a rooted Typst path such as
`#image("/logo.jpg")` when a nested template needs `assets/logo.jpg`. Paths are
case-sensitive and extensions are not interchangeable. Studio keeps binary
asset bytes in blob storage and resolves them by content hash; an application
database table is not required.

The `assets` option on `renderTypst` is for runtime-provided bytes, such as a
customer-specific signature fetched during the procedure. It is separate from
the system-owned static `assets/` directory.

Use `readBlob` when a generated file must be attached to an email:

```ts
s.readBlob(sql`invoice.pdf_blob`, { defContentScalar: "pdf_bytes" });
s.defScalar("pdf_base64", sql`bytes.to_base64(pdf_bytes)`);
s.sendEmail({
  from: "billing@example.com",
  to: sql`recipient_email`,
  subject: sql.lit`Invoice`,
  htmlBody: sql.lit`<p>Attached.</p>`,
  attachments: [{
    name: "invoice.pdf",
    content: sql`pdf_base64`,
    contentType: "application/pdf",
  }],
});
```

## ZIP And Spreadsheet Exports

Use `s.createZip(...)` when exporting many blob-backed files. The query string
must return `archive_path` plus either `blob_hash` (`sourceType: "BlobHash"`) or
bytes content (`sourceType: "Bytes"`).

```ts
s.createZip({
  query: `
    select archive_path, blob_hash
    from export_rows
    order by archive_path
  `,
  sourceType: "BlobHash",
  compression: "Store",
  defOutputScalar: "zip_bytes",
});
s.setHeader(sql.lit`Content-Type`, sql.lit`application/zip`);
s.return(sql`zip_bytes`);
```

Use `s.queryToExcel(...)` or `s.queryToCsv(...)` for tabular exports. For simple
CSV buttons in UI, use `DownloadButton` from `components/download_button`.

Keep export queries deterministic: include stable filenames, content types, and
ordering so repeated exports are predictable.

## Print Queues

Use [PrintersBlock](../blocks/printers.md) for printer and label workflows
instead of a custom queue table. Render the document or label, store it with
`s.createBlob(...)`, then call `enqueueDocument` or `enqueueRaw` inside the
same transaction that changes the related record. The block owns the
`print_jobs` table, edge delivery, attempt tracking, explicit retry, and a jobs
page for operators.

Treat printers as external workers. Do not block user-facing UI while waiting
for a physical printer to complete.
